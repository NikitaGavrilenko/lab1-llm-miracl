# Лабораторная №1 — MIRACL (русский язык)

Работа связана с ВКР по взаимодействию LLM с поисковыми инструментами. Реализован **контролируемый reranking** размеченных кандидатов MIRACL, а не полнокорпусный поиск и не полноценный многошаговый агент. Это ограничение принципиально: MIRACL не содержит эталонных агентных траекторий.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python experiment.py download
python experiment.py prepare --limit 100 --seed 42
```

`prepare` также получает размеченные фрагменты через `datasets.load_dataset('miracl/miracl','ru',...)`. Возможно, потребуется принять условия доступа к датасету на Hugging Face и выполнить `hf auth login`. Для некоторых версий `datasets` загрузка legacy dataset script требует доверия к скрипту; устанавливайте зависимости только из проверенного источника.

Укажите OpenAI-совместимый адрес сервера и имя модели из списка в `experiment.py` (на сервере модели должны быть доступны):

```bash
export OPENAI_BASE_URL=http://localhost:8000/v1
export OPENAI_API_KEY=not-needed
python experiment.py evaluate --models Qwen/Qwen2.5-7B-Instruct
python experiment.py summarize
```

Для восьми моделей опустите `--models`, если сервер действительно обслуживает все восемь. При перебое повторная оценка продолжится по отсутствующим (модель, режим, запрос). Итоги появляются в `results/summary.csv`.

## Методика

- Один и тот же срез MIRACL ru dev и seed 42 для всех моделей.
- Zero-shot и few-shot (2 коротких примера); одинаковые кандидаты и формат JSON.
- Основные метрики: nDCG@10, Recall@10, MRR; 95% bootstrap CI; доля невалидных JSON; p95 latency.
- При ошибке/невалидном JSON применяется BM25 fallback, который **входит** в оценку; доля таких случаев считается отдельно.
- Для честного сравнения используйте одинаковый сервер/железо, версию модели, максимальную длину контекста и настройки генерации; убедитесь, что список кандидатов помещается в контекст.

## Ограничения

В evaluation pool входят только размеченные релевантные и нерелевантные пассажи каждого запроса. Значения не сравнимы напрямую с официальным MIRACL leaderboard, где поиск ведётся по полному корпусу. Recall@10 при числе кандидатов меньше 10 может насыщаться; в таком случае основной показатель — nDCG@10. Данные MIRACL не содержат отдельных labels классов тональности, вероятностей релевантности и пошаговых действий агента: MCC, ECE/Brier и многошаговую точность в этой постановке не вычисляем. Необходимы отдельные эксперименты с полнотекстовым индексом и синтетическими/размеченными многошаговыми траекториями.
